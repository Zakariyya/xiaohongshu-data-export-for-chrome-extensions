# 后台定时全量导出实施计划

目标：支持每隔 X 小时或每天本地固定时间，使用唯一 Chrome alarm；不打开助手页面、不抢焦点。

已确认方案：后台运行现有 9 项导出；临时小红书标签页 active=false，结束后关闭。保留现有手动导出人工接力。自动模式失败只记录，不等待人工输入。

实现步骤：
- [x] 为计划验证、跨日计算、重复恢复及关闭功能写 Node 测试，先验证失败。
- [x] 新增 schedule.js：配置校验、单个固定名称 alarm、持久化 nextAt、串行更新、防重复触发。
- [x] dashboard.js 兼容 service worker：隔离全局、UI 可选、后台临时标签、报告 data URL、全局互斥锁、异常清理。
- [x] background.js 连接 alarm 和执行器，记录后台运行和中断状态。
- [x] 添加设置、下次运行及上次结果；更新 README 和版本。
- [x] 运行 Node 模拟 Chrome API 的行为测试、语法检查、diff 检查。真实账号下载需在用户 Chrome 验收。

边界：不唤醒电脑；错过多个周期只补一次；每天重新按本地日期计算，支持夏令时。浏览器崩溃中断不自动重试下载。浏览器下载位置询问、连续下载权限及站点后台渲染行为无法由插件保证。

验证结果：
- Node 行为测试 12/12 通过，包含完整 9 项导出模拟、无下载不挂起、登录失败清理、互斥跳过、计划恢复与去重、中断标签页清理。
- 真实隔离 Chromium 加载扩展通过：间隔/每日保存、刷新保留、单个 alarm、关闭清除；页面持有 Web Lock 时真实 alarm 触发后台并记录 skipped，未创建额外页面。页面无 JS 错误。
- JavaScript 语法检查、git diff --check 通过。
- 未登录真实小红书账号；站点后台实际下载、系统下载提示及长任务受浏览器生命周期影响仍需用户 Chrome 验收。
